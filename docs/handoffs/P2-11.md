Known gaps / follow-ups:
- Default queue depth (`3`) and review count (`5`) come from the committed synthetic example snapshot, not P2-02/P2-03 services. They are labelled synthetic/stale-capable in every row; no live claim is made. Real adapters should implement the four public protocols and be injected via `collect_dashboard`.
- `P2-02` had no handoff or files in `services/triage/queue/` at implementation time. Unavailable providers are therefore first-class: `depth=None`/`completed=None` render as `unavailable — no queue provider configured` / `unavailable — no review provider configured`, never as zero.
- Failure rate is the prevalence of fixture labels (`stt_wrong`, `parser_wrong`, `unusable_audio`) in the 36 synthetic turns (10/36). The fixture manifest has no observation timestamp, so that metric is explicitly `unknown (no timestamp)` and stale. It is **not** a production error rate and does not implement the 3–5% unbiased live random slice (context.md §2.6). Triage scores are hints, not labels, and were deliberately not used as a label source.
- Model version and last promotion are unknown by default. The example snapshot records `null` for both, so no version or timestamp is invented. A future release/MLflow adapter must inject `ModelStateSnapshot`/`PromotionRecord` with `source`, `promoted_at` and optional audit reference; absent values render exactly `unknown / no version recorded` and `unknown / no promotion recorded`.
- `stale_after_minutes` (default 1440) is a display-only freshness hint, never a gate or promotion threshold. The renderer is read-only: it does not evaluate artifacts, flip aliases, or perform rollback.
