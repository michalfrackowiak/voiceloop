Known gaps / follow-ups:
- No real MLflow adapter, Docker runner, network call or GPU work exists by design: the logger is an in-memory fake and the artifact URI is fake by default. A production adapter only needs `MlflowLogger.log_run(TrainingRun)`; the seam is documented in the core README.
- `SingleJobLock` is per-interpreter only. Multi-process exclusion needs an injectable `FileJobLock` implementation (OS-level file lock, `fcntl.flock`/`msvcrt.locking`) from infra/orchestration; the interface is documented but not implemented here.
- Default `git_sha` is 40 zeros and the default image digest is a pinned fake; production orchestration must inject real values via `VOICELOOP_TRAINERS_*`.
- No CLI was added; downstream plugins register with `TrainerRegistry` and call `TrainerRunner` directly. P2-10 owns orchestration.
